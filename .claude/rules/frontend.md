# Frontend conventions

- Next.js App Router. Every route lives under `app/[locale]/`; the locale (`fr`, `en`) is
  always in the URL, with `hreflang` alternates. Server Components by default; `"use client"`
  only where there is state, an effect or a browser API
- Import through the `@/` alias, never `../../`
- Every API call goes through `services/`: one file per area (`showcases.ts`, `me.ts`…)
  exporting typed functions and their TanStack Query keys. Components never call `fetch`
- Types come from `lib/api/schema.d.ts`, generated by `pnpm api:types` (openapi-typescript)
  from the backend's springdoc. Never hand-write a type the API already describes
- Two fetch wrappers: `lib/api/server.ts` (`serverGet`) calls `API_INTERNAL_URL` and forwards
  the session cookie; `lib/api/client.ts` (`clientPost`, `clientPut`) calls the same-origin
  `/api` with the CSRF token. Public reads shared by every visitor (catalogue, showcase page)
  fetch without a cookie inside a `"use cache"` service instead
- Text on screen comes from `messages/{fr,en}.json` through next-intl's `getTranslations`, on
  the server. Client components receive translated strings as props: no
  `NextIntlClientProvider`, no `useTranslations` in the browser, because they ship the ICU
  message parser to every visitor (measured: 149.9 → 136.5 KB of initial JS without it). No
  literal string in JSX, no `toLocaleDateString` without the locale: format on the server with
  `getFormatter`
- Internal links are `next/link` with `localizedPath(locale, path)` from `i18n/paths.ts`; in a
  client component, `withoutLocale(usePathname())` gives the path without its locale. Not
  next-intl's navigation helpers (they need the client provider)
- Tailwind only, with the tokens of the `design-system` skill (`bg-canvas`, `text-ink`,
  `bg-accent`…); never a raw hex in a class. No inline style unless the value is computed at
  runtime
- Interactive primitives (sheet, dialog, menu, tabs, toggle group) are Radix, wrapped once in
  `components/ui/`. No shadcn/ui import that drags Lucide in
- Icons are components from `components/icons/`, generated by SVGR from `icons/*.svg`;
  never an icon library
- Forms use React Hook Form with a Zod schema; the schema's messages are translation keys
- Props are typed with `interface XxxProps`; hooks are `useXxx` under `hooks/`; pure
  helpers go to `lib/`
- Performance budget: ≤ 150 KB of compressed initial JavaScript, LCP < 2.5 s in 4G on a
  low-end Android. Images through `next/image` (AVIF/WebP, `sizes`), screenshots lazy, loaded on
  tap when `navigator.connection.saveData` is on. Skeletons, never a full-screen spinner
- Returning from a showcase to the catalogue restores the scroll position: non-negotiable
- Validate with `pnpm typecheck && pnpm lint && pnpm build`. A check against API fixtures
  proves the UI, not the integration with the live backend
